# 外部准点触发：手把手配置

## 这是在干什么

签到脚本住在 GitHub 上，需要有「人」每天到点按一下开始键。

- GitHub 自带的定时器：**按了但不准时**（实测 09:30 的活拖到 14:14，20:30 那次直接没按）
- 所以找个外部闹钟网站 cron-job.org：**每天 09:30 / 20:30 准点帮你按一次**

按一下的动作 = 向 GitHub 发一个 HTTP 请求（POST），地址是固定的那串 URL，token 就是通行证。

---

## 第 1 步：在 GitHub 建一把「钥匙」（token）

1. 手机/电脑打开：<https://github.com/settings/personal-access-tokens/new>
   （路径：GitHub 头像 → Settings → 最下面 Developer settings → Personal access tokens → Fine-grained tokens → Generate new token）
2. 按下面填：

| 字段 | 填什么 |
|---|---|
| Token name | `checkin-cron` |
| Expiration | `1 year` |
| Resource owner | `liziliangli73-max`（默认就是这个，别改） |
| Repository access | 选 **Only select repositories** → 下面下拉框选 `checkin` |

3. 往下滚到 **Permissions** → 点开 **Repository permissions** → 找到 **Actions** → 右边下拉选 **Read and write**。其它不用动。
4. 拉到最底部点绿色 **Generate token**。
5. 页面会显示一串 `github_pat_xxxxxxxx`，**只显示这一次**。点复制，先粘到手机备忘录里。

> 这串东西等于密码，别发到聊天里、别提交进仓库。

---

## 第 2 步：注册 cron-job.org

1. 打开 <https://cron-job.org/en/signup/>
2. 填邮箱 + 密码 → 点 **Sign up**
3. 去邮箱点验证链接 → 回来登录

---

## 第 3 步：建第一个任务（早上 09:30）

登录后点 **Create cronjob**（或 Cronjobs → Create cronjob），按下表填：

| 页面上的字段 | 填什么 |
|---|---|
| **Title** | `签到-早` |
| **URL** | `https://api.github.com/repos/liziliangli73-max/checkin/actions/workflows/glados.yml/dispatches` |
| **Enable job** | 保持勾选 |

然后在同一页往下找 **Advanced**（高级设置，可能是个折叠区块，点开），设置：

**Request method**（请求方式）→ 选 `POST`

**Headers**（请求头）→ 点 **Add header** 加 4 条：

| Name | Value |
|---|---|
| `Authorization` | `Bearer github_pat_你的token` |
| `Accept` | `application/vnd.github+json` |
| `X-GitHub-Api-Version` | `2022-11-28` |
| `Content-Type` | `application/json` |

> `Bearer` 后面有一个空格，再接 `github_pat_...`

**Request body**（请求内容）→ 粘贴：

```json
{"ref":"main"}
```

**Save responses**（保存响应）→ 建议勾上，出问题能看到原因。

再往下是 **Execution schedule**（执行时间）：

- 选「每天 / Every day」
- 时间填 `09:30`
- 时区选 `Asia/Shanghai`（找不到就选 `UTC` 并填 `01:30`）

最后点 **Create / Save**。

---

## 第 4 步：测试

1. 回到任务列表，找到「签到-早」，点右边的 **TEST RUN**（▶ 图标）
2. 看结果：

| 返回 | 含义 |
|---|---|
| **204** | ✅ 成功。GitHub 成功收到，本来就不返回内容 |
| 401 | token 错、少写了 `Bearer `、或者已经过期 |
| 404 | URL 写错，或 token 没勾这个仓库 |
| 422 | body 里 `"ref":"main"` 写错 |

3. 去 <https://github.com/liziliangli73-max/checkin/actions> 看，应该多出一条 **workflow_dispatch** 的运行记录。
4. 再过 1 分钟刷新签到台，页面上「最近检查」的时间会跳到刚才那一刻。

---

## 第 5 步：复制出第二个任务（晚上 20:30）

在任务列表里对「签到-早」点 **Duplicate**（复制），只改两处：

- Title → `签到-晚`
- 执行时间 → `20:30`

保存，再 TEST RUN 一次。

---

## 配好之后长什么样

- 每天 09:30 和 20:30，cron-job.org 各发一次请求
- GitHub 收到就跑签到脚本：当天没签就签，已签就跳过（只刷新「最近检查」）
- 签到台「最近更新」只在真签到时变，「最近检查」每次都变
- cron-job.org 的 **Status notifications** 打开，任务失败会邮件通知你

## 常见问题

- **204 是不是失败了？** 不是，204 就是成功。
- **token 过期怎么办？** 到期前 GitHub 会提示，重新生成一串，把两个任务的 Authorization 头改掉即可。
- **能在手机上配吗？** 能，全程都是网页操作。
- **GitHub 自己那个 12:00 的定时还要吗？** 留着当保险，不影响。
