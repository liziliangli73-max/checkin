# 外部准点触发：手把手配置（中英对照）

## 关于界面语言

GitHub 和 cron-job.org **都没有官方中文版**。用 Chrome 的「翻译此页」之后，按钮会变成中文，但**机器翻译的说法每次可能不一样**（比如 Headers 可能被译成「标头」或「请求头」）。

所以下面每个字段都写成「中文（English）」两栏对照，照着任一边找都能对上。

> 说明：这一页是**可选升级**。现在不加也能用——GitHub 那边已经排了一天 8 个时段（06:00 / 08:30 / 09:30 / 12:00 / 14:30 / 17:00 / 19:30 / 21:30），漏一个还有别的兜底。这一页解决的是「想做到分秒不差」。

## 这是在干什么

签到脚本住在 GitHub 上，需要有「人」每天到点按一下开始键。

- GitHub 自带的定时器**按了但不准时**（实测 09:30 的活拖到 14:14，20:30 那次直接没按）
- 所以找个外部闹钟网站 cron-job.org，**每天 09:30 / 20:30 准点帮你按一次**

按一下 = 向 GitHub 发一个 POST 请求；URL 是固定的地址，token 就是通行证。

---

## 第 1 步：在 GitHub 建一把「钥匙」（token）

1. 打开 <https://github.com/settings/personal-access-tokens/new>
2. 按下表填：

| 中文界面 | 英文原文 | 填什么 |
|---|---|---|
| 令牌名称 | Token name | `checkin-cron` |
| 到期时间 | Expiration | `1 year`（1 年） |
| 资源所有者 | Resource owner | `liziliangli73-max`（默认，别改） |
| 仓库访问权限 | Repository access | 选 **仅选择仓库 / Only select repositories** → 下拉勾 `checkin` |

3. 往下滚到「**权限 / Permissions**」→ 展开「**仓库权限 / Repository permissions**」→ 找到「**操作 / Actions**」→ 右边下拉选「**读取和写入 / Read and write**」。别的都别动。
4. 拉到最底部，点绿色按钮「**生成令牌 / Generate token**」。
5. 页面出现一串 `github_pat_...`，**只显示这一次**。复制，先粘到备忘录。

> 这串等于密码。别发聊天、别提交进仓库。

---

## 第 2 步：注册 cron-job.org

1. 打开 <https://console.cron-job.org/signup>（注意是 **console**.cron-job.org，`cron-job.org/en/signup` 是 404）
2. 邮箱 + 密码 → 点「**注册 / Sign up**」
3. 去邮箱点验证链接，回来登录：<https://console.cron-job.org/login>

---

## 第 3 步：建第一个任务（早上 09:30）

登录后点「**创建定时任务 / Create cronjob**」（顶部按钮，或菜单 Cronjobs → Create cronjob）。

**上半部分，基本信息**

| 中文界面 | 英文原文 | 填什么 |
|---|---|---|
| 标题 | Title | `签到-早` |
| 网址 | URL | 下面那串长地址 |
| 启用任务 | Enable job | 保持勾选 |

```
https://api.github.com/repos/liziliangli73-max/checkin/actions/workflows/glados.yml/dispatches
```

**中间部分，点开「高级 / Advanced」**

| 中文界面 | 英文原文 | 怎么设 |
|---|---|---|
| 请求方法 | Request method | 选 `POST` |
| 标头 / 请求头 | Headers | 点「添加标头 / Add header」，加下面 4 条 |
| 请求正文 / 请求体 | Request body | 粘贴 `{"ref":"main"}` |
| 保存响应 | Save responses | 建议勾上，出错能看到原因 |

4 条标头（左列 Name / 名称，右列 Value / 值）：

| 名称 | 值 |
|---|---|
| `Authorization` | `Bearer github_pat_你的token` |
| `Accept` | `application/vnd.github+json` |
| `X-GitHub-Api-Version` | `2022-11-28` |
| `Content-Type` | `application/json` |

> `Bearer` 和 token 之间**有一个空格**。

**下半部分，执行时间**

| 中文界面 | 英文原文 | 填什么 |
|---|---|---|
| 执行计划 / 时间表 | Execution schedule | 选「每天 / Every day」 |
| 时间 | Time | `09:30` |
| 时区 | Timezone | `Asia/Shanghai`（没有就选 UTC，时间填 `01:30`） |

最后点「**保存 / Create / Save**」。

---

## 第 4 步：测试

1. 任务列表里找到「签到-早」，点「**测试运行 / TEST RUN**」（▶ 图标）
2. 看返回的状态码：

| 返回 | 含义 |
|---|---|
| **204** | ✅ 成功，GitHub 本来就不返回内容 |
| 401 | 钥匙不对：`Bearer ` 少空格 / token 复制不全 / 已过期 |
| 404 | 网址写错，或 token 没勾这个仓库 |
| 422 | `{"ref":"main"}` 写错 |

3. 打开 <https://github.com/liziliangli73-max/checkin/actions>，应多出一条 `workflow_dispatch` 的运行。
4. 等 1 分钟刷新签到台，「最近检查」会跳到刚才那一刻。

---

## 第 5 步：复制出晚上的任务

任务列表里对「签到-早」点「**复制 / Duplicate**」，只改两处：

- 标题 → `签到-晚`
- 时间 → `20:30`

保存，再「测试运行」一次。

## 对照速查（Chrome 翻译常出现的几种说法）

| 英文 | 可能译成 |
|---|---|
| Token | 令牌、代币、标记 |
| Repository access | 仓库访问权限、存储库访问 |
| Permissions | 权限 |
| Generate token | 生成令牌 |
| Create cronjob | 创建定时任务、新建计划任务 |
| Request method | 请求方法 |
| Headers | 标头、请求头、标题（这个最容易翻错，别看错） |
| Request body | 请求正文、请求体 |
| Execution schedule | 执行计划、时间表 |
| TEST RUN | 测试运行、试运行 |

## 常见问题

- **204 是不是失败了？** 不是，204 就是成功。
- **token 过期了？** 重新生成一串，把两个任务的 `Authorization` 值换掉。
- **能在手机上配吗？** 能，全程网页操作。
- **GitHub 自己的 8 个时段还要吗？** 留着，不影响。
