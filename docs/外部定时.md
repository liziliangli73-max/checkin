# 外部准点触发（cron-job.org）

GitHub 自带的 `schedule` 不可靠：实测 09:30 的活拖到 14:14，20:30 那次直接没跑。因此主力改成由外部定时器准点调用 GitHub API 触发本 workflow，GitHub 自己的 cron 只保留中午 12:00 一个兜底。

## 1. 建一个只对这个仓库有效的 token

GitHub → 头像 → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token

| 项 | 值 |
|---|---|
| Token name | `checkin-cron` |
| Expiration | 1 year（到期要换） |
| Resource owner | `liziliangli73-max` |
| Repository access | Only select repositories → 只勾 `checkin` |
| Permissions → Repository permissions | **Actions: Read and write**（其余全 None；Metadata 会自动带上 Read） |

生成后复制 `github_pat_...`（只显示一次）。

## 2. cron-job.org 建两个任务

注册 <https://cron-job.org>（免费）→ Create cronjob，两个任务配置相同，只有执行时间不同。

**URL**

```
https://api.github.com/repos/liziliangli73-max/checkin/actions/workflows/glados.yml/dispatches
```

**Method**：`POST`

**Headers**

```
Authorization: Bearer github_pat_你的token
Accept: application/vnd.github+json
X-GitHub-Api-Version: 2022-11-28
Content-Type: application/json
```

**Body**

```json
{"ref":"main"}
```

**Schedule**

| 任务 | cron（时区选 Asia/Shanghai） | 含义 |
|---|---|---|
| 早 | `30 9 * * *` | 每天 09:30 |
| 晚 | `30 20 * * *` | 每天 20:30 |

建好后点 **TEST RUN**：返回 **204 No Content** 就是成功（GitHub 就是这么回的，没有内容正常），几秒后 Actions 里能看到一条 `workflow_dispatch` 运行。cron-job.org 还能开执行失败邮件通知。

## 3. 验证

- Actions 页面出现 `workflow_dispatch` 的运行 → 触发器通了
- 签到台「最近检查」跟着跳到对应时间 → 全链路通了
- 当天已签时，脚本会跳过并只刷新「最近检查」，属正常

## 排错

| 现象 | 原因 |
|---|---|
| 401 | token 错或过期 |
| 404 | 仓库名/workflow 文件名写错，或 token 没勾这个仓库 |
| 422 | body 里的 `ref` 分支名不对（应为 `main`） |
| 204 但没运行 | 看 Actions 是否被禁用；本 workflow 的 `workflow_dispatch` 触发器被删了也会这样 |

## 换掉的旧方式

`on.schedule` 里的 `30 1 * * *`（09:30）和 `30 12 * * *`（20:30）已删除，只留 `0 4 * * *`（北京 12:00）兜底。原因是 GitHub 会把定时任务排进队列慢慢等，高峰期还可能整次丢弃。
